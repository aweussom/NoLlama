# N-001 — Cut v1.0.0?

**Decided:** 2026-09-18 · **Decision:** (a) tag it now. The runtime version string
stays date-based — `v1.0.0` is a milestone on the release page, not a return to
semver.

**Cost:** 30 min · **Asks:** Tommy

## What

`v0.9.0` was tagged 2026-08-11 and **220 commits** ago. Its own commit message
reserved 1.0.0 for "after the web-UI markdown/scroll PR (#23) lands". #23
landed, and so did embeddings (#43), VLM tool calling, VLM prefix caching, the
Phi-3.5-vision fix, Docker packaging and the `_vlm_penalty_guard`.

The version string is date-based (`_version_string()`: `<date>` from a release
ZIP, `<date>-<commit>` from a checkout), so a tag is the only thing that marks
a release. There is nothing to bump in code.

## The decision

- **a)** Tag `v1.0.0` now. The NPU honesty pass (commit `28f58d9`) was the last
  thing anyone called a blocker.
- **b)** Wait for a `compose` smoke test on a clean box, since Phase 3 shipped
  but `DOCKER-INSTALL.md` is the only thing that has exercised it.
- **c)** Wait for a native Linux `/dev/dri` result (T-026), because #31 asks for
  it and a 1.0 that has never run on native Linux invites the issue straight
  back.

Session's lean: **a**. Linux is confirmed working by a user (issue #6) even
without our own run, and 220 commits of unreleased work is the bigger risk —
release-ZIP users are on August code.

## Saying yes means

Pick a letter. On (a): tag, push the tag, write the release notes from
`STATUS.md` and the commit log.
